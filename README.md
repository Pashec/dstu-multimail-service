# ДГТУ Рассылка (версия 3.0)

Автономное десктопное приложение для автоматизированной персонализированной отправки писем, генерации вежливых обращений, распределения персональных вложений и бесшовного встраивания страниц PDF (чертежей, схем, бланков, таблиц и печатей) прямо в тело письма.

---

## Эволюция: сравнение с версией 2.0

Версия 2.0 заложила фундамент модульной архитектуры и базовую отправку по Excel, однако в условиях реальной работы на кафедрах и в деканатах ДГТУ требовался качественно иной уровень надежности, визуализации и контроля.

Ниже приведено детальное сравнение версии 2.0 и версии 3.0:

| Возможность / Подсистема | Версия 2.0 (DSTU Multi-mailer v2.0) | Новая версия 3.0 (ДГТУ Рассылка) |
| :--- | :--- | :--- |
| **Отображение PDF** | PDF прикреплялся только как обычный файл вложения. Встроить страницы чертежей или бланков в само письмо было невозможно. | Бесшовное графическое встраивание страниц PDF (чертежи КОМПАС/AutoCAD, рамки по ГОСТ, синие гербовые печати, таблицы) в высоком разрешении через PyPDFium2 прямо в тело письма. |
| **Комплектация вложений** | Адресат получал только один персональный файл (либо Word, либо PDF). | Одновременная отправка и персонального Word (.docx), и персонального PDF (.pdf) одному адресату: PDF раскрывается в письме, Word идет вложением. |
| **Предпросмотр перед отправкой** | Отсутствовал. Запуск выполнялся вслепую, проверить подстановку тегов и вид письма до отправки было нельзя. | Интерактивный «Предпросмотр письма» (Live Preview): просмотр готового письма с реальными страницами PDF (Base64 Data URI) и навигацией по адресатам. |
| **Проверка данных (Dry Run)** | Отсутствовала. Ошибочные почты или отсутствие файлов выявлялись только в процессе боевой рассылки. | Кнопка «Проверить список» (Dry Run): проверка синтаксиса email, выявление опечаток в доменах (@gmai.com, @donstu.com) и перечень адресатов без файлов. |
| **Работа с шаблонами писем** | Текст и тему нужно было каждый раз набирать заново или копировать из внешнего блокнота. | Встроенный менеджер шаблонов: 3 предустановленных университетских бланка ДГТУ + сохранение и удаление собственных шаблонов в один клик. |
| **Режимы адресации** | Только через таблицу Excel. Для отправки одного письма приходилось создавать отдельный файл .xlsx. | Переключатель режимов: «По списку Excel» для массовой рассылки и «Одиночный адресат» для быстрой отправки конкретному человеку. |
| **Надежность SMTP и антиспам** | Разовые соединения. При любой сетевой заминке или коде 4xx строка падала в ошибку. Паузы не было. | Пул соединений Keep-Alive (без постоянных переподключений), Auto-Retry с повтором до 3 раз при сбоях сети, кнопка «Пауза / Продолжить». |
| **Сохранение учетных данных** | Логин и пароль не сохранялись, их требовалось вводить заново при каждом запуске программы. | Защищенное автосохранение: пароль шифруется через Windows Data Protection API (DPAPI) с привязкой к учетной записи Windows. |
| **Отчетность по итогам** | Логи оставались только на экране в окне программы и исчезали при закрытии. | Автоматическое формирование детализированного Excel-отчета (.xlsx) со статусами + кнопки «Открыть отчет» в Excel и «Показать в папке». |
| **Интерфейс и темы** | Длинная форма со скроллом, базовые цвета, резкие частицы. Ошибка WinError 5 при выходе из WebView2. | 3 комфортные темы («Тёмный графит», «Светлый ДГТУ», «Тёплый комфорт»), логичное разделение полей, интерактивные частицы, чистый выход без ошибок. |

## Архитектура и стек технологий

Проект организован по модульному принципу:
* **Бэкенд:** Python 3.10–3.12, FastAPI, Uvicorn, aiosmtplib, OpenPyXL, Jinja2.
* **Обработка документов:** PyPDFium2 (рендеринг PDF-страниц в высоком разрешении без рамок), PyPDF, Pillow, Pymorphy3 (автоматическое определение пола и вежливые обращения).
* **Пользовательский интерфейс:** HTML5, CSS3 (переменные тем, матовые стеклянные карточки с размытием, адаптивная сетка), Vanilla JavaScript, интерактивный Canvas с мягкой реакцией на курсор.
* **Десктопная оболочка:** PyWebView (системный движок Microsoft Edge WebView2).
* **Сборка:** PyInstaller (упаковка в единый автономный исполняемый файл `DGTU_Rassylka.exe`).

## Как запускается и используется программа

### 1. Основной режим: готовый файл DGTU_Rassylka.exe
* Программа работает как единый автономный файл `DGTU_Rassylka.exe`.
* Для конечного пользователя (сотрудника деканата, кафедры, преподавателя) установка не требуется: файл копируется в любую папку и запускается двойным кликом.
* Установленный Python на компьютере не нужен: веб-сервер, интерпретатор, движок интерфейса и библиотеки уже вшиты внутрь файла.
* Служебные файлы создаются автоматически рядом с программой:
  * `credentials.json` — зашифрованные логин и пароль почты (DPAPI).
  * `window_state.json` — сохраненные координаты и размеры окна.
  * `webview_storage/` — рабочий кэш браузерного движка (без мусора в Temp).
  * `reports/` — папка со всеми созданными отчетами в формате .xlsx.

### 2. Сборка нового .exe из исходников
Если вы изменили код или верстку и хотите скомпилировать обновленный файл:

1. Откройте терминал в папке проекта:
   ```bash
   cd dgtu_rassylka
   ```
2. Активируйте виртуальное окружение:
   ```cmd
   venv\Scripts\activate
   ```
3. Запустите сборщик:
   ```bash
   python build.py
   ```
4. Готовый исполняемый файл появится в папке:
   ```
   dist/DGTU_Rassylka.exe
   ```

### 3. Запуск для разработки из исходного кода
1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Запустите приложение:
   ```bash
   python main.py
   ```

## Требования к данным и правила именования

### Таблица получателей (Excel .xlsx)
* Первая строка таблицы должна содержать заголовки.
* Обязательные колонки (регистр не имеет значения): `email`, `фамилия`, `имя`, `отчество`.
* Любые дополнительные колонки (например, `группа`, `должность`, `приказ`) автоматически становятся тегами письма: `{группа}`, `{должность}`.
* Если заполнена колонка `обращение` (например: *«Дорогой коллега»*, *«Студент»*), программа возьмет именно ее, отключив автоопределение пола.

### Именование персональных файлов (Word и PDF)
Алгоритм нечеткого сопоставления (`matching.py`) ищет файлы по фамилии и инициалам:
* `Путину В.В.pdf` или `Путин Владимир Владимирович.pdf`
* `Иванову И.И.docx` или `Иванов Иван.docx`
* Если адресату соответствуют и Word, и PDF, программа встроит PDF в тело письма, а Word прикрепит как персональный файл вложения.

## Верификация и тестирование

Проект покрыт автоматическими тестами:
* Модульные тесты ядра: `python test_app.py` (10 тестов: парсинг, склонения, сопоставление Word+PDF, рендеринг PDF, шифрование DPAPI, отчеты).
* Интеграционные тесты API: `python test_endpoints.py` (9 тестов: проверка всех эндпоинтов, Dry Run, Live Preview и открытие отчетов).
